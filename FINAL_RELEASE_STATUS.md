# MINDORA Frontend — final source release status

**Status: source release candidate; not production-certified.**

## Included

- Root-level Next.js application for the public, patient, therapist and admin experiences.
- The updated `/forgot-password` and `/reset-password` routes are in the actual root Next.js app, not left hidden in a nested project directory.
- Auth API calls target `NEXT_PUBLIC_API_URL` (default `https://api.mindora.rw`) and use the V3 auth routes.
- Reset screen reads the single-use token from the `token` query parameter, validates and confirms a new password, and posts to the V3 reset endpoint.
- Railway Dockerfile uses Next.js standalone output, Node 24 and port 8080 by default.
- Older Dashboard VII, chatbot client and official website projects are retained separately in `companion_apps/` and excluded from the root app build. They are not claimed as independently integrated or production-ready.

## Required before production

1. Use Node.js 24.16.0. Run `RUN_MINDORA_FRONTEND_CHECKS.cmd` from this folder. It runs `npm ci`, formatting, TypeScript, ESLint, Jest coverage and the Next production build.
2. Review and commit any formatting changes generated by the script.
3. Set `NEXT_PUBLIC_API_URL=https://api.mindora.rw` and `NEXT_PUBLIC_SOCKET_URL=https://api.mindora.rw` in Railway before the Docker build. `NEXT_PUBLIC_*` values are embedded at build time.
4. Confirm Railway target port 8080 and the existing app domain `app.mindora.rw` remain configured.
5. Confirm Kong allows credentialed CORS from `https://app.mindora.rw` and the refresh cookie domain is configured as `.mindora.rw` if required by the existing authentication architecture.
6. Test login, refresh, forgot-password, reset-password, booking, therapist onboarding, admin workflows and chatbot on staging using test accounts.
7. Do not route the legacy Dashboard VII to V3 production APIs until its legacy REST API contract is mapped and verified endpoint by endpoint.
8. Obtain MINDORA approval before production deployment. This archive does not merge PRs, change DNS or deploy to Railway.

## Verification performed while preparing the archive

- Root application placement and route paths inspected.
- API base URL, reset API payload shape, Docker port, workflow and Next.js standalone configuration inspected.
- Source configuration and ZIP integrity checked when this release archive is created.

## Not verified in this environment

- `npm ci`, TypeScript, ESLint, Prettier, Jest, Next.js production build or Docker build: Node available here was 22.16.0, while the project requires 24.16.0, and npm registry access was unavailable.
- Live API, CORS, auth cookies, reset-email delivery, external providers, Railway environment and DNS.

Do not describe this source archive as production-ready until the required CI checks and staging verification above actually pass.
